# 실운영 준비 런북

순서를 지키는 것이 중요하다. **기능을 더 만드는 것보다, 실제로 카톡이 나가고 사진이 돌아오는지 확인하는 것이 먼저다.**

---

## STEP 1. 알림톡 업체 연동 (회사에서 할 일)

1. 카카오톡 채널 비즈니스 인증 (이미 있으면 생략)
2. 발송 대행사 계약 — 솔라피(권장, 어댑터 구현 완료) / NHN Cloud / 알리고 등
   - 솔라피 외 업체를 쓰면 `STONEKIM_MSG_PROVIDER=http` 로 범용 어댑터를 쓰거나 `src/messaging.js` 만 수정하면 된다
3. 발신번호 사전등록 (문자 대체발송용, 통신서류 필요)
4. `docs/알림톡-템플릿-신청.md` 내용으로 템플릿 3종 신청 → **영업일 2~3일 소요**
5. 승인 후 환경변수 설정

```bash
STONEKIM_MSG_PROVIDER=solapi
STONEKIM_SOLAPI_API_KEY=...
STONEKIM_SOLAPI_API_SECRET=...
STONEKIM_KAKAO_PFID=KA01PF...
STONEKIM_MSG_SENDER=0322000000
STONEKIM_TPL_FIRST=KA01TP...
STONEKIM_TPL_SECOND=KA01TP...
STONEKIM_TPL_FINAL=KA01TP...
STONEKIM_BASE_URL=https://photo.stonekim.co.kr
```

6. 점검

```bash
node scripts/check-provider.js                       # 빠진 설정이 있으면 이름을 알려준다
node scripts/check-provider.js 010-XXXX-XXXX --send  # 본인 번호로 실제 1건
```

**확인 사항**: 카톡으로 도착하는가 / 버튼을 누르면 업로드 페이지가 열리는가 /
일부러 템플릿 코드를 지우고 다시 보내면 문자(LMS)로 대체발송되는가.

---

## STEP 2. 실제 출고 엑셀 적용 (직원 양식 그대로)

직원이 지금 쓰는 파일을 **그대로** 넣어 본다. 서버에 올리기 전에 진단부터 한다.

```bash
node scripts/check-excel.js "2026-09 출고내역.xlsx"
```

출력에서 볼 것:

- 필수 4개(주문번호·출고일·고객명·휴대폰번호)가 `✓` 로 잡히는가
- 전화번호 오류 건수가 비정상적으로 많지 않은가 (유선번호·공란은 정상적으로 걸러짐)
- 시공예정일이 `미정` 으로 잘 읽히는가

**직원에게 엑셀 양식을 새로 맞추라고 하지 않는다.** 컬럼명이 안 잡히면
`src/import.js` 의 `HEADER_ALIASES` 에 회사에서 쓰는 표기를 한 줄 추가하면 끝난다.

```js
order_number: ['주문번호', '주문 No', '수주번호', '전표번호', ...여기에 추가],
```

20~30건으로 돌려 보고, 문제가 없으면 관리자 화면에서 업로드 → 미리보기 → 등록.

---

## STEP 3. 사장님 번호로 전체 플로우 실전 테스트

가짜 주문 1건으로 처음부터 끝까지 휴대폰에서 돌려본다. (**카카오톡 인앱브라우저**로 열어야 의미가 있다)

| # | 동작 | 확인할 것 |
|---|---|---|
| 1 | 엑셀 1건(본인 번호, 시공예정일=어제) 업로드 → 등록 | 미리보기에 정상 1건 |
| 2 | 주문 상세 > `지금 1차 발송` | 카톡 수신 |
| 3 | 카톡 버튼 클릭 | 업로드 페이지 열림, 리워드 기준 보임 |
| 4 | 사진 3장 선택 → 동의 체크 → 등록 | 1분 내 완료, 완료 화면 |
| 5 | 관리자 > 주문·현장 | 상태 `사진등록`, 사진 3장 |
| 6 | 주문 상세 > 발송 이력 | 2차 메시지가 `사진등록 취소` 로 바뀌었는지 **(가장 중요)** |
| 7 | 사진 검수 > ★ BEST / 사용가능 지정 | 반영됨 |
| 8 | 리워드 5만원 + 지급완료 저장 | 리워드 목록·대시보드 반영 |
| 9 | 업로드 링크 다시 열기 | 중복 등록 안 되고 완료 화면 |

6번이 안 되면 **절대 오픈하지 않는다.** 이미 사진 보낸 고객에게 또 조르는 것이 가장 큰 사고다.

아이폰 사용자는 4번에서 HEIC 사진으로도 한 번 해본다(자동으로 JPEG 변환된다).

---

## STEP 4. 소규모 오픈 (30~50명)

1. 관리자 `설정 > 일일 발송 한도` 를 **30~50** 으로 설정 (0 = 무제한이므로 반드시 값을 넣는다)
2. 과거 고객 엑셀에서 30~50건만 잘라 업로드
3. 클레임·반품·취소 고객은 등록 후 즉시 `자동 메시지 발송 제외` 처리
4. 3~5일 지켜보며 대시보드의 아래 지표를 본다

| 지표 | 의미 | 낮을 때 원인 |
|---|---|---|
| 알림톡 성공률 | 발송 자체 문제 | 번호 오류, 채널 차단, 템플릿 문제 |
| 업로드 페이지 방문률 | 카톡은 갔는데 안 누름 | **메시지 문구·리워드 매력도 문제** |
| 사진 등록률 | 눌렀는데 안 올림 | **업로드 UX·사진 장수 부담 문제** |
| 1차/2차/최종 단계별 등록 | 재발송 효과 | 2차에서 거의 안 늘면 재발송 주기 재검토 |

방문률은 높은데 등록률이 낮으면 시스템이 아니라 **최소 3장 요구·입력 항목·동의 문구**를 의심한다
(설정에서 최소 장수를 2장으로 낮춰 A/B 확인 가능).

---

## STEP 5. 전체 오픈 전 점검

- [ ] 일일 발송 한도를 실제 운영 규모로 조정
- [ ] `설정 > 관리자 작업 로그` 로 오발송 이력 없는지 확인
- [ ] 리워드 지급 프로세스(계좌 수집 방법) 확정 — 현재 MVP 는 지급 여부만 관리, 실제 송금 없음
- [ ] 개인정보 처리방침·동의 문구 최종 검토(법무)
- [ ] 관리자 비밀번호 변경, `STONEKIM_SECURE_COOKIE=1` (HTTPS)
- [ ] `data/` 폴더 백업 주기 결정 (사진 원본 + DB)

## 운영 중 자주 쓰는 것

| 상황 | 조치 |
|---|---|
| 클레임 고객에게 발송 막기 | 주문 상세 > `자동 메시지 발송 제외` |
| 고객이 카톡으로 사진을 보냄 | 주문 상세 > `사진 직접 등록` (이후 자동발송도 중단됨) |
| 시공이 미뤄짐 | 주문 상세 > 시공예정일 변경 → 1차 재예약 |
| 지금 당장 보내야 함 | 주문 상세 > `지금 1차 발송` |
| 전체 발송 급히 중단 | `설정 > 일일 발송 한도 = 1` 로 낮추거나 서버 중지 |
| 발송 실패 원인 확인 | `발송 로그` 의 비고 열 (업체 오류코드 그대로 기록됨) |
